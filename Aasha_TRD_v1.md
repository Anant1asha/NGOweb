## 1. System Architecture

### 1.1 High-Level Architecture

Aasha is a build-time pipeline that transforms NCERT PDFs into self-contained HTML files. There is no runtime backend — the output is a single HTML file that runs entirely in the browser.

```
┌─────────────────────────────────────────────────────────┐
│                    BUILD PIPELINE                        │
│                                                          │
│  NCERT PDF ──→ Chapter Text ──→ STEPS Array (JSON)      │
│       │              │                  │                │
│       │         pdfminer           AI-generated          │
│       │         extraction         step content           │
│       │                                  │               │
│       │     ┌────────────────────────────┘               │
│       │     │                                            │
│       │     ▼                                            │
│       │  Engine Assembly                                 │
│       │     ├── CSS template (mobile-first, 600px)       │
│       │     ├── LLE Engine (CONN dict + rt() + applyLLE)│
│       │     ├── STEPS JSON (chapter-specific)            │
│       │     └── App Engine (renderers + gamification)    │
│       │                  │                               │
│       │                  ▼                               │
│       │           Validation Gates                       │
│       │             ├── node --check (syntax)            │
│       │             └── Runtime DOM test (all steps)    │
│       │                  │                               │
│       └──────────────────┘                               │
│                          │                               │
│                          ▼                               │
│              Single HTML File (offline)                   │
│              (CSS + JS + data embedded)                   │
└─────────────────────────────────────────────────────────┘
```

### 1.2 Runtime Architecture (In-Browser)

The delivered HTML file contains three major JavaScript components:

```
HTML File (single, offline, ~100KB)
│
├── CSS (embedded <style>)
│   ├── Design tokens (--brand, --green, --gold, etc.)
│   ├── Layout (max-width 600px, sticky header, bottom bar)
│   ├── Step type styles (.we-card, .quiz-opt, .feedback, etc.)
│   ├── Animation (slideIn, pop, pulse, tpulse)
│   └── Responsive (mobile-first, touch-action: manipulation)
│
├── LLE Engine (JavaScript)
│   ├── CONN dictionary (modals + connectors + cue verbs/adverbs/adjectives)
│   ├── WM dictionary (full word-meaning dictionary, for tap-to-reveal)
│   ├── rt(text) function — processes text into tappable + auto-annotated HTML
│   ├── applyLLE() function — applies rt() to all content elements on screen
│   └── showWord() function — opens Hindi meaning dialog on tap
│
├── STEPS Array (JSON)
│   ├── Step objects with type (t) and type-specific fields
│   ├── Chapter-specific content (not generic templates)
│   └── Generated by AI from NCERT chapter text
│
└── App Engine (JavaScript)
    ├── State: sIdx, xp, coins, level, streak, weStepIdx, solveStepIdx
    ├── init() — sets up event listeners, renders first step
    ├── render() — dispatches to step-type renderers
    ├── Step renderers: renderIntro, renderTutor, renderFormula, renderWE,
    │   renderQuiz, renderSolve, renderRapidFire, renderMemoryMatch,
    │   renderMilestone, renderComplete, renderShop
    ├── Sim renderers: renderIxBalance, renderIxPolygonBuilder,
    │   renderIxAngleSum, renderIxExteriorAngle, renderIxQuadExplorer, etc.
    ├── Gamification: updateStats(), checkLevelUp(), confetti()
    ├── Navigation: next(), back()
    └── Assessment: checkQuiz(), checkSolve(), endRF()
```

## 4. LLE (Language Layer Engine) — Technical Specification

### 4.1 CONN Dictionary Specification

The CONN dictionary contains understanding-cue words that are auto-annotated inline. It is divided into three categories:

**Category A: Modals (20 entries)**
Words that express possibility, necessity, obligation, or ability:

```javascript
"can":"सकता है", "could":"सकता था", "will":"करेगा", "would":"करेगा",
"shall":"करेगा", "should":"करना चाहिए", "must":"ज़रूरी है", "may":"सकता है",
"might":"शायद कर सके", "need":"ज़रूरत है", "need to":"ज़रूरत है करना",
"have to":"करना पड़ता है", "had to":"करना पड़ा", "ought to":"करना चाहिए",
"be able to":"सक्षम है", "used to":"पहले करता था", "dare":"हिम्मत करना",
"had better":"बेहतर होगा", "be going to":"करने वाला है", "be supposed to":"करना अपेक्षित है"
```

**Category B: Connectors (80+ entries)**
Words that connect ideas — cause, contrast, condition, sequence, addition, conclusion:

```javascript
// Cause/Effect
"because of":"के कारण", "due to":"के कारण", "since":"क्योंकि",
"therefore":"इसलिए", "thus":"इस प्रकार", "hence":"इसलिए",
"as a result":"परिणामस्वरूप", "so that":"ताकि", "consequently":"परिणामस्वरूप",
// Condition
"if":"अगर", "unless":"जब तक नहीं", "otherwise":"नहीं तो", "then":"तब",
"even if":"भले ही", "only if":"केवल तभी", "provided":"बशर्ते",
// Contrast
"although":"हालांकि", "though":"हालांकि", "however":"हालांकि",
"yet":"फिर भी", "still":"फिर भी", "whereas":"जबकि", "instead":"इसके बजाय",
// Sequence/Time
"before":"पहले", "after":"बाद में", "when":"जब", "while":"जब",

"to sum up":"संक्षेप में", "in short":"संक्षेप में",
// ... (full list in source code)
```

**Category C: Understanding-Cue Verbs, Adverbs, Adjectives**
Words that carry the meaning of the sentence — action verbs, descriptors, and modifiers that, when translated, give the student an instant understanding anchor:

```javascript
"equals":"बराबर है", "means":"मतलब", "gives":"देता है",
"shows":"दिखाता है", "consider":"सोचो", "observe":"देखो",
"notice":"ध्यान दो", "remember":"याद रखो", "always":"हमेशा",
"never":"कभी नहीं", "exactly":"ठीक", "directly":"सीधे",
"important":"ज़रूरी", "equal":"बराबर", "opposite":"विपरीत",
"parallel":"समान्तर", "perpendicular":"लंबवत", "consecutive":"क्रमागत"
// (grows with each chapter — added as needed based on sentence context)
```

**Design rules for CONN entries:**
1. Hindi must be conversational/colloquial, NOT dictionary-formal
   - "because" → "क्योंकि" (not "कारण कि")
   - "should" → "करना चाहिए" (not "कर्तव्य है")
   - "must" → "ज़रूरी है" (not "अनिवार्य है")
2. Hindi must be short — 1-3 words max
3. Hindi must build understanding, not replace English
4. Math domain terms (equation, variable, coefficient, etc.) are NOT in CONN — they are tap-only

### 4.2 rt() Function — Text Processing Algorithm

The `rt(text)` function processes a text string and returns HTML where:
- Understanding-cue words (from CONN) are auto-annotated inline with Hindi (max 4 per sentence)
- All other words are wrapped as tappable elements (`.wd` class)

```
Algorithm:
1. Sort CONN keys by length (longest first) for multi-word matching
2. Initialize connCount = 0
3. Iterate character by character through the text:
   a. On sentence boundary (., !, ?, ,) → reset connCount = 0
   b. On HTML tag (<...>) → pass through unchanged
   c. At word boundary (not preceded by a letter):
      - Try to match each CONN key (longest first)
      - If matched AND connCount < 4:
        → Wrap as .cn (connecting word) with inline Hindi: word (हिंदी)
        → Increment connCount
      - If matched AND connCount >= 4:
        → Wrap as .wd (tappable) with Hindi in data attribute
      - If not matched:
        → Wrap as .wd (tappable) with WM lookup if available
4. Return processed HTML
```

### 4.3 applyLLE() Function

```javascript
function applyLLE() {
  // Selectors for all content-bearing elements
  var sels = ".bt,.we-question,.we-step,.quiz-opt-text,.instruction,.hint,
    .formula-box .f-label,.f-expr,.f-note,.misconception,.correct-method,
    .feedback,.milestone-text,.milestone-next,.discovery-box .d-text,
    .discovery-box .d-title,.intro-title,.intro-sub,.complete-title,
    .complete-sub,.tutor-box,.real-example,.visual-title,.we-tag";
  var els = document.querySelectorAll(sels);
  for (var i = 0; i < els.length; i++) {
    var el = els[i];
    if (el.querySelector(".wd") || el.querySelector(".cn")) continue; // already processed
    if (el.tagName === "BUTTON" || el.tagName === "INPUT") continue;
    var h = el.innerHTML;
    if (!h || h.trim().length < 3) continue;
    try { el.innerHTML = rt(h); } catch(e) {}
  }
}
```

Called after every render to process new content.

### 4.4 Word Dialog (showWord)

When a `.wd` or `.cn` element is tapped:
- Opens `<dialog id="wordDialog">`
- Shows: word (large, purple), Hindi translation (purple), description (gray)
- For `.cn` elements: description = "Connecting word"
- For `.wd` elements: description = brief context or "Hindi meaning not available"

### 5.2 Engine Patches (Applied at Build Time)

The base App code (`build_v3_p4.py`) is patched at build time. These patches represent accumulated learnings from building Chapters 1–3:

#### Patch 1: renderIntro — Dynamic Intro Text
**Problem:** Original code hardcoded a Hindi intro ("Dekho yaar, rational numbers...").
**Fix:** Uses `step.intro` from STEPS data.
```javascript
var introText = step.intro || "Welcome!";
// ... uses rt(introText) to render
```

#### Patch 2: renderWE — Step-by-Step Reveal
**Problem:** Original showed all steps at once.
**Fix:** Uses `weStepIdx` counter. Shows steps 0..weStepIdx. Button: "Next Step (X of Y)".
```javascript
if (this.weStepIdx === undefined) this.weStepIdx = 0;
var idx = this.weStepIdx;
if (idx >= step.steps.length) {
  cb.textContent = "Continue"; cb.className = "btn btn-green";
  return;
}
// Render steps 0..idx with current step highlighted
```

#### Patch 3: renderQuiz — Fisher-Yates Shuffle
**Problem:** Correct answer was always option A.
**Fix:** Shuffles options, stores in `shuffledOpts`.
```javascript
var shuffled = step.opts.slice();
for (var i = shuffled.length - 1; i > 0; i--) {
  var j = Math.floor(Math.random() * (i + 1));
  var t = shuffled[i]; shuffled[i] = shuffled[j]; shuffled[j] = t;
}
self.shuffledOpts = shuffled;
```

#### Patch 4: checkQuiz — Use Shuffled Options
**Problem:** checkQuiz used original step.opts, not shuffled.
**Fix:** Uses `this.shuffledOpts || step.opts`.

#### Patch 5: init() WE Handler — Navigation Fix (CRITICAL)
**Problem:** When worked example finished, weStepIdx was set to `undefined`, render() reset it to 0 → infinite loop.
**Fix:** Reset to 0 and call `next()` to advance.
```javascript
if (step.t === "we" && self.weStepIdx !== undefined && self.weStepIdx < step.steps.length) {
  self.weStepIdx++;
  if (self.weStepIdx >= step.steps.length) {
    self.weStepIdx = 0;
    self.next();  // ← advances to next step, NOT render()
    return;
  }
  self.render();
  return;
}
```

#### Patch 6: render() Reset Logic
**Problem:** weStepIdx/solveStepIdx reset on every render, even within the same step.
**Fix:** Only reset when step changes (tracked via `_prevSIdx`).
```javascript
if (this._prevSIdx !== this.sIdx) {
  this.solveStepIdx = 0;
  this.solveAnswered = false;
  this.weStepIdx = 0;
  this._prevSIdx = this.sIdx;
}
```

#### Patch 7: English Feedback
**Problem:** Feedback was in Hinglish ("Sahi!", "Galat.").
**Fix:** English ("Correct!", "Not quite.", "Why wrong:", "Correct approach:").

#### Patch 8: Step Type Cases
Adds `case` entries for chapter-specific simulation types (ix_balance_sim, ix_polygon_builder, etc.) in the render() switch statement.

#### Patch 9: Simulation Render Functions
Inserts chapter-specific simulation render functions (renderIxBalance, renderIxPolygonBuilder, etc.) into the App object before renderShop.

## 6. Validation Gates

### 6.1 Syntax Check
```bash
node --check output.js
```
Must return exit code 0. Any syntax error fails the build.

### 6.2 Runtime DOM Test

A simulated DOM environment in Node.js that:
1. Creates mock elements for all `getElementById` calls
2. Calls `App.init()`
3. Iterates through all STEPS, calling `App.render()` for each
4. Verifies: all steps render without error, no blank screens
5. Tests WE navigation: simulates clicking through all sub-steps, verifies `sIdx` advances (no infinite loop)
6. Tests quiz shuffle: runs 10 renders, verifies correct answer position varies
7. Checks for duplicate questions across all we/solve/quiz steps

```javascript
// Key test: WE navigation
App.sIdx = weIdx; App.weStepIdx = 0; App.render();
for (var i = 0; i < step.steps.length; i++) {
  App.weStepIdx++;
  if (App.weStepIdx >= step.steps.length) {
    App.weStepIdx = 0;
    var before = App.sIdx;
    App.next();
    assert(App.sIdx !== before, "sIdx must advance — no infinite loop!");
    break;
  }
  App.render();
}
```

### 6.3 Duplicate Question Check

```python
all_questions = [s["q"][:60] for s in steps if s["t"] in ("we", "solve", "quiz")]
dupes = [q for q in all_questions if all_questions.count(q) > 1]
```

## 7. Build Process (Per Chapter)

### 7.1 Step-by-Step Build

1. **Extract chapter text** from NCERT PDF using pdfminer
   ```python
   from pdfminer.high_level import extract_text
   text = extract_text(pdf_path, page_numbers=list(range(start, end)))
   ```

2. **Generate STEPS array** — AI creates JSON with chapter-specific content:
   - intro (with `intro` field for chapter-specific text)
   - tutor segments (learning content with real-life analogies)
   - formula boxes (key formulas with labels)
   - worked examples (NCERT "Example N" — unique questions)
   - quiz checkpoints (different questions from examples)
   - solve assessments (NCERT "Exercise X.Y QZ" — unique)
   - simulations (chapter-specific ix_* steps)
   - milestone, rapid_fire, memory_match, complete

3. **Verify no duplicate questions** — all we/solve/quiz questions must be unique

4. **Load patched App code** from `/workspace/notes/app_final.py`

5. **Load LLE v2 engine** from `/workspace/notes/build_v3_p2_v2.py`

6. **Assemble HTML**: CSS template + LLE engine + STEPS JSON + App code

7. **Syntax check**: `node --check`

8. **Runtime test**: Simulated DOM test (all steps render, WE advances, quiz shuffles)

9. **Deliver**: `workspace_emit` + `present_output`

### 7.2 Build Constraints

- STEPS array generated using `json.dumps(steps, ensure_ascii=False)` — prevents encoding issues
- All Hindi text in Devanagari script (UTF-8)
- File size target: < 150KB
- Zero external dependencies (no CDN, no API, no images)
- ASCII-only filenames
- Max-width: 600px

## 9. Gamification Mechanics

### 9.1 XP and Leveling

| Action | XP | Coins |
|--------|-----|-------|
| Correct quiz answer | +5 | +2 |
| Correct solve step | +5 | +2 |
| Memory match pair | +10 | +3 |
| Milestone reached | +50–80 | +10 |

### 9.2 Streak System

- Each consecutive correct answer increments streak
- Any wrong answer resets streak to 0
